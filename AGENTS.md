# ia-tenis Project Context

## Overview
Tennis match prediction model (ATP/WTA/Davis Cup) with Elo + features + logistic calibration, an interactive value-bet analyzer, an automated daily scanner, and a visualization dashboard.

## Architecture
- **EloSystem** (`src/models/elo.py`): General + surface Elo ratings with yearly decay, K-factor based on match count
- **FeatureBuilder** (`src/features/engineering.py`): Recent win rates, momentum (3/5-match), H2H rate + trend, surface win-rate trend, rest days
- **EloHistoryTracker + decay features** (`src/features/decay.py`): Rolling Elo, age/rust/fatigue/surface-transition multipliers
- **Pipeline** (`src/pipeline.py`): Load → build features → walk-forward backtest, tour-agnostic (atp/wta/davis)
- **Value Analysis** (`src/value_analysis.py`): LR model + shrinkage calibration + odds API + interactive CLI (`--wta`/`--davis`)
- **Backtest** (`src/backtest/walkforward.py`): Walk-forward LR evaluation with mirror rows; sorts by `match_date` with `kind="stable"` so appending newer rows never reshuffles same-day historical matches (and thus never changes their features); `return_predictions=True` exposes raw (prob, outcome) pairs (including a mirror-balanced `probs_calibration`/`y_true_calibration` pair) for calibration analysis
- **Calibration metrics** (`src/calibration_metrics.py`): Reliability/calibration-curve analysis against the large backtest sample (never the small real-bet log — see `docs/metrics/2026-09-18-calibration-investigation.md`). **Global calibration is not betting edge**: `scripts/market_edge_backtest.py` replays the production bet rule on out-of-sample WTA predictions against Tennis-Data historical odds (2016–2026) — the de-vigged market beats the model (log-loss 0.595 vs 0.622, optimal blend weight on the model = 0), and the rule's picks lose −12.3% flat (95% CI −15.0..−9.5) vs −7.2% for betting every side, with theoretical EV +19% matching the real log. ATP (`--tour atp`; odds from Tennis-Data ATP files downloaded once to gitignored `data/raw/tennis_atp_tduk_odds/`, joined by last-surname-token + initial within a tournament date window): same picture as WTA once the round-order leak was fixed — market log-loss 0.579 vs model 0.609, blend weight on the model 0, the rule loses −10.6% at average odds vs −7.1% betting every side. `--anchored` adds market-anchored walk-forward models (M1 logit(q); M2 + logit(p_model); M3 + the 15 features; no intercept, sign-symmetric): they are essentially the market (≤0.6 millinats better) and find almost no 3% edges at average odds — no current feature adds information the price lacks. `scripts/serve_stats_edge.py` tested opponent-adjusted ATP serve/return stats (Tennismylife per-match stats + iid point model): they improve the standalone model by ~4.6 millinats of log-loss but add only ~0.2 over the market and no profitable bets — already priced in, deliberately not in `FEATURE_COLS`. See `docs/metrics/2026-10-07-model-vs-market-edge.md`
- **Dashboard** (`src/dashboard.py`): Backtest accuracy by year, calibration curves, LR feature importance, value-bet history — PNGs to `data/dashboard/` (gitignored, regenerate with `python -m src.dashboard`)
- **Daily scanner** (`src/daily_scanner.py`): Discovers live matches via The Odds API, no staleness gate (prints warnings only), `--auto-save`, `--in-play` (opt-in, loud warning — model has no live-match-state signal), rate-limit retry with backoff. The required tournament-index request (`fetch_sports_index`) also retries transient failures (429/5xx, `URLError`, timeouts) via `_fetch_sports_index_with_retry` and still raises once exhausted — added after the 2026-10-06 run died on a `ConnectionResetError` there. Before logging a value bet, calls `check_existing_log_entry()` (`src/value_analysis.py`): a genuinely new match logs normally, odds within 2% of an already-logged pending match is skipped as a duplicate, odds moved >2% updates that row in place (`update_log_entry()`) instead of appending a second one, and a match whose row already has a real result is never touched. Added 2026-09-19 after a re-scan of the same still-pending match logged it twice, which would have double-counted the position once it settled. That fix only guards future scans — it doesn't retroactively clean history, and indeed the two pre-existing Stearns/Jovic rows it was built to explain (odds 3.80 and 3.90) were still both present in the real `value_bets_log.csv` until the 2026-09-19 production verification found and removed the stale one (kept the fresher row); `tests/test_value_bets_log_integrity.py` now asserts the real log has no duplicate-identity pending rows so this can't silently reappear. `classify_audit_decision()` used to label every "had value but wasn't logged" row `passed_user_declined`, including auto-skipped duplicates and, in the daily workflow, excluded-tour picks and sub-`MIN_EDGE` edges. Since 2026-10-07 it takes a `passed_reason` (`PASSED_REASONS`): `passed_duplicate`, `passed_tour_excluded`, `passed_below_min_edge`, and `passed_user_declined` only when a human actually said no; `compute_audit_coverage()` counts all four. Rows written before that keep the old catch-all label.

**2026-09-19 investigation — `UNKNOWN_RECOVERY` in the audit log**: 7 rows (timestamps 2026-08-21 through 2026-08-27, real players/odds/probabilities, valid `model_commit` references to real commits from that week) carry `decision == "UNKNOWN_RECOVERY"`. That string appears nowhere in `classify_audit_decision()` (past or present — checked the function's content at all 4 referenced `model_commit` hashes) and nowhere else in tracked git history as code, only ever as data in commit `15cbf3f` (the commit that first added `prediction_audit_log.csv` to git, importing the file's pre-existing content wholesale). Both current call sites of `log_prediction_audit()` (`src/daily_scanner.py`, `src/value_analysis.py`) always compute `decision` via `classify_audit_decision()` first — there is no path in current code that can pass a hardcoded literal. Conclusion: some uncommitted, ad-hoc script from that week called `log_prediction_audit()` directly with `decision="UNKNOWN_RECOVERY"` as an honest placeholder (real prediction was evaluated and worth recording for calibration purposes, but the script had no way to know what classification a live scan run would have assigned — none of the 7 matches appear in `value_bets_log.csv`, ruling out a "reconstructed from the bet log" theory). **Not a bug in current code** — `tests/test_calibration_audit.py::test_audit_log_no_unknown_recovery_in_code` now exhaustively checks all 64 boolean input combinations of `classify_audit_decision()` and asserts none can ever produce it. **Decided not to delete the 7 rows**: they're genuine historical predictions (real odds/probabilities/edges), not corrupt or duplicated data, and the audit log's whole purpose is to preserve "the full population of predictions" for calibration — deleting them would destroy real data to tidy up one metadata field. The only downstream consumer of `decision` is `backtest_analytics.compute_audit_coverage()`, which degrades gracefully (`.get(cat, 0)` against a fixed category list — these 7 rows just don't show up in any per-category bucket, undercounting the breakdown by 7 out of 609, though `total`/`logged`/`passed` stay correct since `passed = total - logged`).
- **Daily workflow** (`scripts/daily_workflow.py`): Stricter automation wrapper — DOES hard-exclude a tour (ATP, WTA and Davis independently) on any staleness (unless `--live-tournament` opts out of that), keeps picks with edge >= 3% at 1/4 Kelly, auto-logs + emails + git-pushes. Tours in `AUTO_LOG_EXCLUDED_TOURS` (currently `{"wta", "atp", "davis"}` since 2026-10-07 — no demonstrated edge vs the market, see the market-edge backtest below; Davis has no odds to test and the ATP model predicts its rubbers better than the Davis-specific model, whose Elo is built from Davis matches only (median 4 per player). Nothing is auto-logged at all now, so the daily email reports "0 pick(s)" — but since 2026-10-07 it also lists the excluded tours' qualifying picks as "signals" (tracked for CLV, never bet; the subject adds "N senal(es) en seguimiento"), plus an odds-snapshot/CLV panel from `scripts/clv_report.summary()` (wrapped so a reporting failure never breaks the run)) are still scanned and written to the audit log but never logged as bets or emailed; remove a tour only with new evidence from `scripts/market_edge_backtest.py`. `--tour`, `--days-ahead`, `--no-push` (log + email, no commit/push), `--dry-run`. Backs up both logs before writing, applies the same `check_existing_log_entry()` dedup/update as the scanner, and classifies audit rows by what was actually logged
- **Telegram** (`src/utils/telegram.py`, since 2026-10-07): after the email, `daily_workflow` posts the day's **predictions** -- per match, the model's win probability for each player (favourite in bold), grouped by tournament, kickoff in Lima time, bookmaker full names -- for every match the model can rate (Elo found and 25+ matches for both players), to `TELEGRAM_CHAT_ID`, a **public channel ("Momentum Bet", bot @AnalystGG_bot is an admin)**. By the user's choice it posts **no picks, odds or edges** (a first version posted qualifying picks; replaced the same day), only a one-line footer that these are model estimates, not betting advice. Nothing is posted when there is nothing to rate, on `--dry-run`, or with `--no-telegram`. Never raises, and never prints the request URL (it contains the bot token). Tests must never post: `tests/test_daily_workflow.py` has an autouse fixture replacing `send_telegram_predictions`. Token/chat id live in the repo `.env` (copied from the `.env` in `C:/Users/ERICK/Documents/Codex/`). `DiscoveredMatch.commence_time` (ISO UTC from The Odds API) exists for this display
- **Runner** (`scripts/run_prediction.py`): download → pipeline → retrain (non-interactive `load_model(tour, retrain=True)`, never the interactive CLI) → `scripts.daily_workflow --no-push` (since 2026-10-07; previously `daily_scanner --auto-save`), `--log` writes `data/logs/daily_{date}.log`, `--dry-run` passes through to the workflow (full pipeline, no log writes/email/push). Every step runs with `cwd=ROOT`, so it works from any working directory
- **Settlement** (`scripts/settle_workflow.py`): asks for each pending bet's winner (a/b/skip — never fetches results automatically, a scraped source once hallucinated a score), computes profit (`kelly*(odds-1)` win / `-kelly` loss), writes `docs/metrics/{date}-jornada-{tournament-slug}.md`, commits and pushes. The slug comes from the settled rows' tournaments (`_report_filename`: ATP/WTA/Davis prefix dropped, duplicates collapsed, e.g. `us-open`); until 2026-10-07 it was hardcoded to `cincinnati`, and the 7 mislabeled Monterrey/US Open reports were renamed. For settling without the interactive prompt (or without pushing), reuse its `_compute_profit`/`_write_rows`/`_build_report` helpers; the 7 US Open bets pending since early September were settled this way on 2026-10-07 after cross-checking winners against the Tennismylife/Tennis-Data match data and explicit user confirmation
- **Scheduler** (`scripts/schedule_daily.py`): Builds/removes a Windows Scheduled Task for `run_prediction.py`. - **Odds snapshots** (`scripts/snapshot_odds.py`, since 2026-10-07): builds the opening-vs-closing line history Tennis-Data lacks (its historical odds are closing only). Each run fetches h2h odds for every active ATP/WTA tournament (`regions=eu`, 1 credit per tournament) and appends to `data/odds_snapshots/{YYYY-MM}.csv` only the (event, bookmaker) rows whose prices changed; pre-match only (started matches skipped). Every run is logged in `data/odds_snapshots/runs.csv` — with change-only rows, that is what proves a price was still current at a given time. The Odds API key is on the free plan (500 credits/month, shared with the daily scan at ~3 credits per tournament per day): a run stops spending once remaining credits would drop below `--min-remaining` (default 150, env `ODDS_SNAPSHOT_MIN_REMAINING`). The data is irreplaceable (can't be refetched without a paid historical plan) and is git-tracked: the scheduled task passes `--commit`, which makes a local commit of only `data/odds_snapshots/` at most once every 24 h (`src/git_utils.commit_paths`, leaves anything else the user staged alone, never pushes). Scheduled via `python scripts/schedule_daily.py --odds-snapshots` (task `ia-tenis-odds-snapshots`, every 6 h from 01:00, output to `data/logs/odds_snapshots.log`). **2026-10-07**: `schtasks /create` defaults keep a task from starting on battery — on the production laptop the snapshot task just sat "Queued", and the daily prediction task had the same setting. Both create functions now follow `schtasks /create` with a PowerShell `Set-ScheduledTask` (`-AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -StartWhenAvailable`); both tasks were re-registered and the snapshot task verified end-to-end via `Start-ScheduledTask`
- **CLV report** (`scripts/clv_report.py`, since 2026-10-07): closing-line value of the model from the odds snapshots — the fast test of "betting early" (hundreds of matches, no results needed). Joins every audit-log prediction to its snapshot event (tour + both players' last-surname|initial key in either order + commence date within a day; the audit log has no event id), takes the fair line at the last run before the scan (`q_scan`) and each bookmaker's last pre-match price (`q_close`, only if a run happened within `--max-close-gap-hours`, default 8, of the start), and reports (A) the slope of the line move (q_close − q_scan) on the model's disagreement (p − q_scan), with an event-clustered bootstrap CI — > 0 means the market moves toward the model after the scan — and (B) the mean CLV (`odds × q_close − 1`) of the production rule's picks at the scan's logged best odds. The audit log had no rows from 2026-09-21 until the daily task was re-registered on 2026-10-07, so data starts 2026-10-08
- **Log backups** (`scripts/backup_logs.py`): timestamped `shutil.copy2` backups of `data/prediction_audit_log.csv`/`data/value_bets_log.csv` to `data/logs/backup_{timestamp}_{filename}.csv` (gitignored, rotated to the last 7 per file), called by `daily_scanner.py` and `daily_workflow.py` right before they write. Tests must never let `backup_logs()` run with its default paths — the keep-last-7 rotation then evicts genuine production backups (happened until 2026-10-07; `tests/test_daily_scanner.py` now has an autouse fixture no-op'ing it). Second line of defense alongside both log files being git-tracked (`!`-negated in `.gitignore`) — added after a 2026-09-19 incident where an ad-hoc dedup script deleted 26 rows from the then-untracked audit log (no unique data was actually lost — see `docs/metrics/2026-09-19-audit-log-protection.md` — but the file had no recovery path at the time)
- **Data Loading** (`src/data/loader.py`): `_clean()` orders ATP/Davis rows by (match_date, tourney_id, round, match_num) with a stable sort — Tennismylife dates every match of a tournament with `tourney_date`, and until 2026-10-07 an unstable sort on match_date alone listed later rounds first in 99% of tournaments, leaking later results into early-round features (`rest_diff` alone beat the closing market; ATP walk-forward accuracy was inflated 66.7% → 68.5%). Never sort these rows on match_date alone. ATP (Tennismylife API) and WTA (tennis-data.co.uk, scraped live for current URLs) loaders; WTA is topped up by the **Valuebetennis supplement** (`src/data/wta_supplement.py`, CC BY 4.0, downloaded by `scripts/download_data.py` to `data/raw/tennis_wta_tduk/valuebetennis_{year}.csv`) because Tennis-Data's current-season file lags (stuck at 2026-09-27 as of early October — see `docs/metrics/2026-10-05-wta-source-lag.md`). Only settled main-draw rows after the primary file's last date are added; full names resolve to existing WTA keys (unknown/ambiguous excluded), ranks carry forward <=35 days, and an all-or-nothing 90% identity-coverage gate keeps a partial supplement from masking staleness. The gate depends on loaded history — loading only 2026 can fail it while the real 2007+ pipeline passes; `load_davis_cup_matches` filters the ATP feed by `tourney_level == "D"` — tennis-data.co.uk has no separate Davis Cup source
- **Config** (`src/config.py`): Environment variables, MIN_MATCHES_THRESHOLD=25, MAX_SUSPICIOUS_EDGE=0.10

## Key Design Patterns
- Mirror rows: every match has a mirrored counterpart (loser's perspective, outcome=0)
- No-lookahead: all features computed sequentially before match update
- Shrinkage calibration: predictions outside [0.10, 0.90] compressed 60% toward boundary (verified near-optimal empirically — see calibration investigation doc; only affects the tails, never the [0.20, 0.80] core range)
- Cache: model persisted in `data/model_cache/{tour}.pkl` with 7-day expiry
- Davis Cup shares ATP's raw directory (`_RAW_TOUR_DIRS`) and staleness mechanism — no separate data source exists

## FEATURE_COLS (15, `src/features/__init__.py`)
`elo_diff, elo_prob, rank_diff, form_diff, surface_form_diff, h2h_rate, rest_diff, rolling_elo_diff, age_multiplier_diff, rust_factor_diff, fatigue_multiplier_diff, surface_transition_multiplier_diff, adjusted_elo_diff, h2h_trend, surface_win_rate_trend_diff`

`momentum_3_diff`/`momentum_5_diff` are computed by `FeatureBuilder` but deliberately **not** in `FEATURE_COLS` — A/B backtest showed no clear benefit and a small net negative when bundled with the other two additions.
